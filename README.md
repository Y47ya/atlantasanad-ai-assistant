# ATLANTASANAD AI Assistant

Production-ready AI Assistant for **ATLANTASANAD Assurance** based on **Retrieval-Augmented Generation (RAG)** and **AI Agents**.

The objective of this project is to build an enterprise-grade assistant capable of answering questions from internal company documentation while integrating business APIs for real-time information. The entire solution is designed to run **locally** using **open-source technologies**, ensuring data confidentiality and compliance with company requirements.

# Current Features

## 📥 Ingestion Pipeline

The ingestion pipeline converts raw PDF documents into semantically searchable vectors stored inside Qdrant.

---

## 1. Document Parsing

The parser extracts the hierarchical structure of PDF documents while preserving document organization.

Current implementation:

- Docling

Output:

```text
Document
├── Metadata
├── Sections
└── Content Blocks
```

---

## 2. Document Cleaning

The extracted document is normalized before semantic processing.

Current cleaning operations include:

- Removing empty blocks
- Removing formatting artifacts
- Normalizing whitespace
- Cleaning invalid content

---

## 3. Section Semantic Metadata Generation

Each section is analyzed using a local LLM in order to generate semantic metadata.

Generated metadata:

- Summary
- Keywords
- Generation metadata

Purpose:

- Preserve section semantics
- Improve retrieval quality
- Avoid redundant contextual embeddings

---

## 4. Recursive Chunking

Each section is recursively split into smaller chunks.

Current strategy:

- Recursive text splitting
- Configurable chunk size
- Configurable overlap

Each chunk contains:

- Chunk ID
- Chunk Index
- Parent Section

---

## 5. Chunk Semantic Metadata

Each chunk receives additional semantic metadata generated by the local LLM.

Generated metadata:

- Summary
- Keywords

These metadata are intended to improve:

- Retrieval
- Reranking
- Final answer generation

---

## 6. Embedding Generation

Each chunk is converted into a dense vector representation.

Embedding model:

```text
BAAI/bge-m3
```

Generated indexing metadata:

- Embedding provider
- Embedding model
- Chunk hash
- Chunking strategy
- Indexed timestamp

---

## 7. Vector Storage

Embeddings are stored inside **Qdrant**.

Each stored point contains:

### Vector

- Dense embedding

### Payload

- Document ID
- File name
- Page number
- Section title
- Chunk ID
- Chunk index
- Original chunk text
- Section summary
- Section keywords
- Chunk summary
- Chunk keywords
- Indexed timestamp

# Retrieval Pipeline

A complete semantic retrieval pipeline has been implemented.

Pipeline:

```text
User Query
      │
      ▼
Query Embedding
      │
      ▼
Dense Vector Search
      │
      ▼
Top-K Candidate Chunks
      │
      ▼
Cross-Encoder Reranking
      │
      ▼
Context Builder
```

---

## Query Embedding

User questions are embedded using the same embedding model employed during indexing.

Model:

```text
BAAI/bge-m3
```

---

## Dense Retrieval

Relevant chunks are retrieved from Qdrant using cosine similarity.

Current implementation:

- Dense vector search
- Configurable Top-K retrieval
- Metadata retrieval

---

## Cross-Encoder Reranking

Retrieved candidates are reranked using a Cross-Encoder model.

Current model:

```text
BAAI/bge-reranker-base
```

Purpose:

- Improve retrieval precision
- Remove noisy candidates
- Select the most relevant chunks before generation

---

## Context Builder

The final context provided to the LLM contains rich information extracted from the retrieved chunks.

Each context block includes:

- Document name
- Page number
- Section title
- Original chunk text
- Section summary
- Section keywords
- Chunk summary
- Chunk keywords

---

# Current Limitations

Although the complete architecture is operational, several limitations have been identified during testing.

## PDF Parsing

Some PDF layouts are not perfectly reconstructed.

Observed issues include:

- Empty sections after parsing
- Incorrect section splitting
- Loss of contextual information in certain document layouts

---

## Semantic Metadata

The current enrichment model occasionally generates metadata in English even when the source document is entirely in French.

This negatively impacts semantic consistency.

---

## Chunking Strategy

Some chunks lose important contextual information because they only contain the body text without explicitly including the section title.

This can reduce retrieval quality for isolated chunks.

---

## Metadata Quality

Very small sections may generate generic or irrelevant summaries.

Keyword generation may also contain spelling inconsistencies.
