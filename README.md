# ATLANTASANAD AI Assistant

Production-ready AI Assistant for ATLANTASANAD Assurance based on **Retrieval-Augmented Generation (RAG)** and **AI Agents**.

The objective is to build an enterprise-grade assistant capable of answering questions from internal company documentation while integrating business APIs for real-time information, all using **open-source technologies** and **local models**.

---

# Current Features

## 📥 Ingestion Pipeline

The ingestion pipeline transforms raw PDF documents into semantically searchable vectors stored in Qdrant.

### 1. Document Parsing

Extracts the hierarchical structure of PDF documents.

**Current implementation**

- Docling

**Output**

```text
Document
├── Metadata
├── Sections
└── Content Blocks
```

---

### 2. Document Cleaning

Normalizes the extracted document while preserving its structure.

Cleaning operations include:

- Removing empty blocks
- Removing formatting artifacts
- Normalizing whitespace
- Cleaning invalid content

---

### 3. Section Semantic Metadata Generation

Each section is analyzed by the local LLM to generate semantic metadata.

Generated metadata:

- Summary
- Keywords
- Generation information

Purpose:

- Improve retrieval quality
- Preserve section semantics
- Avoid embedding duplicated contextual information

---

### 4. Chunking

Each section is recursively divided into smaller chunks.

Current strategy:

- Recursive text splitting
- Configurable chunk size
- Configurable overlap

Each generated chunk contains:

- Chunk ID
- Chunk Index
- Parent Section

---

### 5. Chunk Semantic Metadata

Each chunk receives additional semantic metadata generated by the LLM.

Generated metadata:

- Summary
- Keywords

This metadata will later be used for:

- Better retrieval
- Context reranking
- Improved answer generation

---

### 6. Embedding Generation

Each chunk is converted into a dense vector representation.

Current embedding model:

```text
BAAI/bge-m3
```

Generated indexing metadata:

- Embedding provider
- Embedding model
- Chunk hash
- Chunking strategy
- Indexed timestamp

---

### 7. Vector Storage

Embeddings are stored inside **Qdrant**.

Each stored point contains:

- Vector

Payload

- Document ID
- File name
- Page
- Section title
- Chunk ID
- Chunk index
- Section summary
- Section keywords
- Chunk summary
- Chunk keywords
- Original chunk text
- Index timestamp

---

# Retrieval Pipeline

A complete semantic retrieval pipeline has been implemented.

Pipeline:

```text
User Query
      │
      ▼
Query Embedding
      │
      ▼
Qdrant Vector Search
      │
      ▼
Top-K Relevant Chunks
```

Current implementation:

- Query embedding using **BAAI/bge-m3**
- Semantic vector search with **Qdrant**
- Ranked Top-K retrieval
- Rich metadata retrieval

Example retrieval result:

| Score | Retrieved Section |
|------:|-------------------|
| 0.655 | GARANTIES INNOVANTES |
| 0.607 | GARANTIE OBLIGATOIRE |
| 0.531 | DES GARANTIES QUI FONT LA DIFFÉRENCE |
| 0.486 | POURQUOI CHOISIR AUTO+ |
